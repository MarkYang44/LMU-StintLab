# 内存与赛事文件

本轮优化保留所有原始 CSV、圈数据 JSON、采样设置和既有 HUD 操作。高频历史缓存存储 float64 数值；原始和游戏过滤后通道仍共用完整 20 秒时间轴。显示桶保留极值，因此单帧刹车尖峰不会被平均掉。没有通过降低采样率、缩短历史或删除遥测通道节省空间。

## 模块职责

- buffers.py：按需扩容、有固定上限的数值环形缓存；共享列定义的 CSV 数值行；参考圈和附加遥测矩阵。
- storage.py：后台批量写盘、检查点、显式队列溢出与恢复。排队内容变为完整转义 CSV 行，减少每个字段的 Python 对象。
- reporting.py：流式读取、压缩和原子写入独立 HTML；大型临时流超过 1 MiB 后转为临时文件。结束报告串行处理，避免多个后台报告同时占用大块内存。
- dataview.js：离线解压，按声明长度分配数值矩阵，按需提供行视图。页面不再同时持有原始 CSV、逐行字符串和数十万个数组副本。
- sessionlab.py：最近五圈仅保留摘要；需要稳定参考时重新读取所选实际完整圈。所有完整圈统计仍保留。

复盘的 13 列时间、圈号、距离、六路输入、车速、X/Z 坐标和赛道长度逐点以 float64 保存；没有对输入曲线降采样。原始 CSV 的 UTC、其他坐标和附加字段保持原字节，仍可外部分析。轮胎、燃油、天气和官方导入通道继续嵌入页面。

## 实测范围

Windows x64、CPython 3.13、Edge，同一份约 95.1 MiB / 424,650 条采样记录。下表是对应场景的进程私有内存峰值，浏览器一项为回收临时对象后 JS 堆加外部数据缓冲的总量；它们不能当作所有机器上的保证值。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 生成完整复盘页，私有内存峰值 | 894.3 MiB | 18.9 MiB |
| 完整圈分析，私有内存峰值 | 560.8 MiB | 66.1 MiB |
| 浏览器保留的复盘数据 | 307.6 MiB | 55.6 MiB |
| 80,000 条双通道历史压力测试，私有内存峰值 | 47.4 MiB | 22.3 MiB |
| 23 秒采集核心测试，运行时私有内存，不含 Tk HUD | 33.2 MiB | 20.5 MiB |

采集核心测试目标设为 4000 Hz，实际约 3006 / 3048 Hz，前后相近；实际新数据率还受游戏生产频率及系统调度限制。实际 HUD 会额外使用 Tk、画布和系统库内存。虚拟地址预留不等于物理 RAM。

流式打包增加了 CPU 工作：该例完整复盘生成约 0.8 → 3.6 秒，完整圈分析约 10.9 → 12.7 秒。处理继续在后台进行；这是用少量时间换取显著降低的内存峰值。

## v0.1.3 的代码与运行优化

原 1591 行入口拆为采集、录制、报告、HUD、几何及配置模块，入口约 80 行，详细职责见 [ARCHITECTURE.md](ARCHITECTURE.md)。后台文件操作统一到两线程任务队列，主线程派发完成回调；正常退出会等待已提交的写入。

新增时间索引只遍历可见波形范围，实际采集 / 绘制频率直接用时间首尾计算；官方日志圈条件直接二分原通道时间轴。Windows x64 / CPython 3.13 的合成对比数据如下，结果值和样本数相同：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 8 万条、19 列历史中提取最近 5 秒的 2 万条记录，中位耗时 | 44.9 ms | 14.7 ms |
| 1.2 万个时间戳的实际频率统计，中位耗时 | 4.31 ms | 0.004 ms |
| 六路各 20 万条官方通道，查询圈起点条件，中位耗时 | 64.3 ms | 0.009 ms |
| 上述条件查询的临时分配峰值 | 12.3 MiB | 528 B |
| 23 秒 / 4000 Hz 目标的合成采集核心，运行私有内存 | 21.5 MiB | 17.4 MiB |

采集测试实际约 2835 / 2935 Hz，不含 Tk HUD。该次运行减少约 19% 核心私有内存，主要来自延迟加载 Tk；不能把它当作整个 HUD 的 RAM 降幅或 4000 Hz 实际采样保证。短时间调度与后台系统负载会影响实测速率。波形窗口结果仍有相同数量的行，其峰值分配基本不变；这部分优化降低扫描时间。

增加了环形回绕、时间边界与相等时间、仅访问可见行、完整尖峰与精度、二分查询复杂度、主线程回调、排队写入退出以及场次首帧的回归覆盖。新场次即使与上一场最后一帧 elapsed time 相同，也会记录自己的首帧。

## 既有记录

新赛事自动使用压缩独立网页。旧网页仍能打开；需要批量升级时，在源码目录运行：

~~~powershell
.venv\Scripts\python.exe tools/optimize_reports.py
~~~

工具先逐点校验复盘输入、会话和分析内容；对比页还校验全部圈数据与保存的回放状态。只有新页更小时才替换，旧网页和恢复清单保存到本机 _local/report-backups/。记录中的 recording 状态不会被升级。CSV、圈文件、备注、设置、底图库和原生日志不会改动。

同批 31 场本地记录的活跃赛事目录从约 850.3 MiB 降到 564.2 MiB，减少约 34%。**备份仍占用磁盘，因此保留备份期间不等于立即回收同样多的磁盘空间。** 页面支持本地直接打开，无需网络；压缩格式使用浏览器内置的 [WHATWG Compression API](https://compression.spec.whatwg.org/)，请使用支持该 API 的现代 Edge、Chrome 或 Firefox。

测试覆盖完整样本和精度、缺失值、20 秒高频历史、单帧尖峰、带逗号/引号/换行的 CSV、写盘溢出/失败、圈边界和原始文件保护。另在浏览器验证输入切换、地图缩放、回放、两圈比较，以及保存对比页后重新打开的状态。
